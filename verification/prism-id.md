# FA-88 — Prism id

Authority: stitch's Prism id (afflom/stitch, `src/prism-id.js`), generated byte for byte into `identity/prism-id.mjs` at the commit `identity/stitch.lock` names, inside the template frame `frame.lock` pins. Its decisions (`Stitch.PrismId.*`) are LexLean definitions in stitch's model; Foundry restates none of them. The boundary is `FoundrySpecification::prismIdBoundary`.

There is no sign-in. The frame makes the visitor's device and id on first touch, then this app's session, and a new id sends and asks the relay nothing until it links, removes a device or is recovered. A session is a stitch action for exactly this origin, signed by an active device of the id.

## Local evidence

`cargo test -p repo-conformance --test prism_id` runs the frame's own checks (`node --test --test-name-pattern="the frame's checks" identity/test.mjs`): 8 of 8 pass. The Chromium flow in the same file (first use, reload, a second app linking, removal, recovery from the kit, a used kit refused, no relay request on first use) runs in the template, 15 of 15.

Planted defect, refused, then restored: `verifySession` taking the audience from the envelope instead of the app. The test "a session for another app is refused" fails.
